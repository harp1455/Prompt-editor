# 작업 기록 (WORKLOG)

이 문서는 **다른 Claude 계정·세션이 이어서 작업할 수 있도록** 남기는 인수인계 기록이다.
작업을 할 때마다 맨 아래 "작업 일지"에 날짜와 함께 덧붙이고, "현재 상태"와 "남은 일"을 최신으로 고친다.

## 1. 이 프로젝트가 무엇인가

- 이름: **크랙 프롬프트 스튜디오** (저장소 `harp1455/Prompt-editor`)

## 2. 구조와 설계 결정 (왜 이렇게 했는가)

| 결정 | 이유 |
|---|---|
| 앱 본체는 프레임워크 없는 **HTML/CSS/JS 3개 파일** (`app/`) | 빌드 단계가 없어 exe·apk 양쪽에 그대로 넣을 수 있고, 다음 작업자가 한 파일만 보면 됨 |
| 윈도우는 **Electron** | 파일 저장 대화상자·자동 업데이트(electron-updater)가 네이티브 코드 없이 됨 |
| 안드로이드는 **Capacitor** | 같은 `app/` 폴더를 웹뷰로 감싸기만 하면 됨. `android/` 폴더는 저장소에 넣지 않고 CI에서 매번 생성 |
| 빌드는 **GitHub Actions** (`.github/workflows/build.yml`) | 사용자가 비개발자라 PC에 개발 환경을 깔게 할 수 없음. main 에 push 하면 exe·apk 가 Releases 에 올라감 |
| 버전은 `1.0.<Actions 실행 번호>` 자동 증가 | 사람이 버전을 올릴 필요가 없고, 업데이트 비교가 단순해짐 |
| 저장은 **IndexedDB**(실패 시 localStorage) + JSON 내보내기 | 썸네일 이미지 때문에 localStorage 5MB 한도가 부족할 수 있음 |
| API 키는 기기에만 저장, 내보내기 파일에서 제외 | 파일을 주고받다 키가 새는 것을 막음 |
| 섹션 = 줄 맨 앞 `# `(대분류). `## ` 는 섹션 안에 두고 왼쪽 목록에 하위 항목으로 표시. 합치면 원문과 글자 단위로 동일 | 크랙에 붙였을 때 원문이 달라지면 안 됨 (테스트로 확인함) |
| 사용자의 실제 프롬프트는 **저장소에 넣지 않음** | 저장소가 공개로 바뀔 수 있어서. 대신 가져오기용 JSON 파일을 사용자에게 따로 전달함 |
| Gemini 안전 설정은 `OFF` → 400이면 `BLOCK_NONE` → 4개 카테고리 `BLOCK_NONE` 순으로 재시도 | 모델마다 허용 값이 달라서. 어느 조합이든 차단 없음 |
| 검수 오탐 방지: 버전별 **"의도 메모"** 를 시스템 지시에 넣음 | 사용자가 "의도된 부분을 항상 검수 요소로 본다"고 우려함. 애매한 것은 "의도 확인 필요"로 따로 묶게 지시 |
| 안드로이드 업데이트는 **알림 + APK 다운로드 링크** | 스토어 밖에서 설치한 앱은 OS가 무인 자동 설치를 막음. 윈도우만 완전 자동 |
| 윈도우 창은 `titleBarStyle:'hidden'` + `titleBarOverlay`(투명) | 제목 표시줄을 없애고 앱의 상단 바가 그 자리를 겸함. 창 버튼(최소화·최대화·닫기)은 직접 그리지 않고 **윈도우가 그리는 진짜 버튼**을 겹쳐 씀 → 창 맞춤(스냅) 등 기본 동작이 그대로 유지되고 코드가 적음 |
| 애니메이션은 라이브러리 없이 CSS + 짧은 JS, **transform·opacity 만** 움직임 | 프레임워크를 들이지 않는다는 원칙 유지. 레이아웃을 건드리지 않아 휴대폰에서도 가볍고, 글자수·원문에 영향이 없음 |
| 애니메이션은 설정에서 끌 수 있고(기기 설정 따름/항상 켬/끔), 기본은 기기의 "애니메이션 줄이기"를 따름 | 휴대폰에서 버벅이거나 거슬리면 사용자가 스스로 끌 수 있어야 함 |

### 코드 지도

```
app/index.html     화면 뼈대 (상단 바, 탭, 본문, AI 서랍, 모달 자리)
app/style.css      스타일. 색은 :root 토큰만 사용. 뒤쪽 구역 순서: 유리·그림자 → 상단 바 높이(--top-h) → 윈도우 일체형 창(html.desk) → 움직임
app/app.js         전체 로직. 위에서부터: 한도 상수(L) → 유틸 → 움직임(motionOn, flip*, tabInk, syncChrome) → DB → 상태(S) → 프롬프트 계산
                   → 화면 그리기(view*) → 끌어서 정렬(sortable) → 모달 → 파일 입출력
                   → 설정 → Gemini(gemini, aiSend, runCompress) → 마인드맵(mm*) → 검색
                   → 버전 관리 → 업데이트 확인(checkUpdate) → 동작 모음(A) → 이벤트 연결
app/version.js     버전·저장소 이름. CI가 덮어씀. 'dev' 면 업데이트 확인을 건너뜀
electron/main.js   윈도우 창(제목 표시줄 없는 일체형, TOP_H=46), 외부 링크, API CORS 허용, electron-updater 연결
electron/preload.js  window.desktop (check / install / onUpdate / theme) 노출
scripts/set-version.js  CI에서 버전을 package.json·version.js·build.gradle 에 반영
capacitor.config.json   안드로이드 앱 ID(app.crackprompt.studio), webDir=app
build/icon.png, assets/logo.png   앱 아이콘 원본
```

데이터 모양: `S = { works[], workId, settings, usage }`,
`work = { id, title, desc, thumb, curVer, versions[], notes[], mind, chat[] }`,
`version = { id, name, memo, joinBlank, intent, sections[{id,label,text,on,memo,fold}], kb[{id,name,triggers[],text,on,memo}], starts[{id,name,text,sub,memo}] }`.
`memo`(항목 메모)와 `fold`(접힘)는 화면용 정보다. **크랙에 붙이는 글(`mainText`)·글자수·복사·미리보기에는 절대 넣지 않는다.**
내보내기 파일: `{ app:"crack-prompt-studio", format:1, kind:"all"|"work", works[] }` (확장자 `.cps.json`).

화면 조작은 모두 `data-act="이름"` 클릭 → `A.이름()` 으로 연결된다. 입력은 `data-in="키"` → `input` 이벤트 핸들러.

### 움직임(애니메이션)이 돌아가는 방식 — 고칠 때 꼭 읽을 것

- `render()` 는 화면을 통째로 다시 그린다. 그래서 **"화면이 바뀌었는가"를 `render.key`(작품/버전/탭)로 구분**한다.
  - 바뀌었으면 `main` 에 `view-in` 클래스를 붙여 CSS 등장 애니메이션(아래에서 떠오름, 목록은 차례로)을 튼다.
  - 같은 화면을 다시 그린 것이면 `view-in` 을 떼고, 대신 **FLIP**(`flipSnap` → 다시 그림 → `flipPlay`)으로 자리가 바뀐 카드만 이전 위치에서 미끄러져 오게 한다. 새로 생긴 카드는 `.pop`.
  - `view-in` 을 떼지 않으면 체크박스 하나만 눌러도 전체가 다시 떠올라 깜빡이니 주의.
- FLIP 대상은 `FLIP_SEL`(`.card,.sticky,.work,.navgrp`) 중 **자기 id 나 data-id 가 있는 것**뿐이다. 새 목록에 넣으려면 항목에 고유 id 를 주면 된다. 같은 이름표가 둘이면 건너뛴다.
- 모달: `#modal` 이 비어 있는지로 "열림"을 판단하는 코드가 여럿 있어서, 닫을 때 `#modal` 은 **즉시 비우고** 사라지는 모습은 `modalOut()` 이 떼어 낸 복사본(`.ov.closing`, id·data-* 제거)이 0.2초 보여 준 뒤 지운다. 열려 있는 모달의 내용만 바꿀 때는 `noanim` 이 붙어 다시 튀지 않는다.
- AI 서랍: `renderAI()` 안에서 열림(`.in`)·닫힘(`.out` → 0.2초 뒤 hidden)을 처리. 서랍이 열리면 본문 폭이 바뀌므로 `regrow()` 로 입력칸 높이를 다시 잰다.
- 탭 밑줄: 탭을 다시 그릴 때마다 `<i class="ink">` 를 새로 넣고 `tabInk()` 가 이전 위치 → 새 위치로 옮긴다. 좁은 화면에서는 고른 탭이 보이도록 탭 줄을 옆으로 옮긴다.
- 끄기: `motionOn()` 이 거짓이면 JS 움직임은 건너뛰고, CSS 는 `html[data-motion="off"]` 가 전부 0초로 만든다. 설정값은 `S.settings.motion`(`auto`/`on`/`off`).
- 상단 바 높이는 CSS 변수 `--top-h` 하나로 정한다(넓은 화면 46px, 좁은 화면 44px, 윈도우 앱은 항상 46px). 윈도우 앱 값은 `electron/main.js` 의 `TOP_H` 와 **같아야** 창 버튼 높이가 맞는다.

## 3. 현재 상태

### 끝낸 것 (브라우저 자동 테스트로 확인)

- 작품 목록 / 새 작품(붙여넣기 자동 분할) / 복제 / 삭제 / 썸네일
- 프롬프트 탭: 섹션 목록(끌어서 순서 변경), 섹션별 글자수, 전체 7000자 미터, 포함 끄기, 위·아래, 커서에서 나누기, 합치기, 복사, 삭제
- 로어북 탭: 20슬롯·400자·트리거 5개 한도, 끌어서 순서 변경, 겹치는 트리거 경고, 발동 테스트(3개 초과 경고)
- 시작상황 탭: 3개, 첫 장면 1000자 + 서브 컨텍스트 1000자
- 미리보기 탭: 메인 전체 복사, 로어북·시작상황 항목별 복사
- 아이디어 노트, 마인드맵(노드 추가·이동·삭제·확대·개요 복사)
- 버전 관리(복제해 새 버전, 이름·메모, 삭제, 전환)
- 치환 규칙 탭: 프롬프트에서 규칙 후보 자동 감지, 규칙별 사용 횟수(원래 표현/기호)·혼용 표시, 규칙별 또는 전체 통일·풀기, 선언 넣기, 선언 줄 복사
- 규칙 모음 탭: AI가 뽑은 통제 규칙을 9개 분류(치환·금지·문체·대사·출력형식·전개·관계·기억·정보·기타)로 정리, 누르면 해당 위치로 이동, 바뀐 섹션만 재분석
- 검색(Ctrl+K, 결과를 누르면 해당 위치로 이동), 되돌리기(큰 변경 15단계)
- JSON 내보내기·가져오기(파일, 텍스트 복사·붙여넣기)
- AI 서랍: 대화·빠른 버튼 8종·압축(약/중/강, 적용 전 비교·수정)·사용량(토큰·달러·원)
- 업데이트 확인 배너, 설정의 버전 표시와 수동 확인 버튼
- 윈도우 일체형 창(제목 표시줄 없음, 상단 바를 잡고 끌어 이동, 창 버튼은 상단 바 오른쪽 끝) — 리눅스용 Electron 33 을 실제로 띄워 확인(아래 "확인하지 못한 것" 참고)
- 항목 메모: 섹션·로어북 슬롯·시작상황마다 "메모" 단추. 프롬프트·글자수에 들어가지 않음. 검색됨, 내보내기·버전 복제에 포함됨, AI 에게 보내는 자료에 "항목별 제작자 메모"로 함께 감(검수가 의도를 알도록)
- 섹션 접기·펴기(섹션별, 모두 접기/펴기). 접힌 상태는 저장됨. 목록·검색·규칙 모음에서 이동하면 자동으로 펴짐
- 찾아 바꾸기(검색 창 안): 프롬프트·로어북 내용·시작상황 글만 대상, 되돌리기 가능
- 두 버전 비교(버전 관리 창): 메인 프롬프트 줄 단위 비교(달라진 부분 강조), 로어북·시작상황 변경 목록, 글자수 변화

### 확인하지 못한 것 (이 작업 환경에서는 실행할 수 없었음)

- **실제 Gemini API 호출**: 키가 없고 외부 접속이 막혀 있어 가짜 응답으로만 검증했다. 실제 모델 이름(`gemini-3.8-flash` 등)과 단가는 2026-11 검색 결과에 따른 참고값이다. 틀리면 설정의 "목록 불러오기"와 단가 입력으로 고칠 수 있게 해 두었다.
- **윈도우에서의 일체형 창 모습**: 리눅스용 Electron 으로는 창 테두리가 사라지고 창 버튼 자리(`titlebar-area`)가 잡히는 것, 상단 바가 끌기 영역으로 잡히는 것, 테마 변경이 창에 전달되는 것까지 확인했다. 하지만 **실제 윈도우에서 창 버튼이 투명 배경으로 잘 겹쳐 보이는지, 끌기·두 번 눌러 최대화·창 맞춤이 되는지는 사용자 PC 에서 확인이 필요하다.** 창 버튼 배경이 어색하게 보이면 `electron/main.js` 의 `overlay()` 에서 `color` 를 불투명 색(밝게 `#f7f9fc`, 어둡게 `#18202a`)으로 바꾸면 된다.
- **실제 휴대폰에서의 애니메이션 부드러움**: 데스크톱 크롬의 휴대폰 흉내(400px·360px, 터치)로 동작과 오류만 확인했다. 오래된 기기에서 버벅이면 설정에서 끄면 되고, 원인은 유리 효과(`backdrop-filter`)일 가능성이 크다.
- **exe 실행, apk 실행**: 빌드는 GitHub Actions 에서만 된다. 설치 후 동작(파일 저장 대화상자, 안드로이드 공유 시트, 자동 업데이트)은 사용자의 실제 기기에서 확인이 필요하다.
- 안드로이드 `Capacitor.Plugins.Filesystem/Share` 호출은 문서 기준으로 작성했고 실기기 검증 전이다. 실패하면 "텍스트로 복사" 경로를 쓰도록 안내 문구가 뜬다.

### 2026-11-16 (4) — 치환 규칙 탭

- 사용자 요청: 프롬프트 안의 치환 규칙을 읽어 통일하거나 모아 보고, 다른 단어도 치환에 넣어 전체 변환하고, 규칙을 추가하는 기능.
- 구현(`app.js` 의 "치환 규칙" 구역): 규칙은 버전마다 `subs[{id,long,short,bulk}]` 로 저장. `long`=원래 표현, `short`=기호.
  - `subDetect`: 본문에서 `A=B` 꼴 중 한쪽만 기호(이모지·원문자)인 것을 후보로 찾음. 같은 기호에 `{{...}}` 규칙이 있으면 그것만 남기고, `≠` 가 든 설명문은 제외.
  - `subApply`: 규칙을 선언한 글자(`원래표현=기호`)는 건드리지 않고 나머지만 바꿈. 한글 낱말은 바로 앞 글자가 한글이면 건너뜀("안대헌" 속 "대헌" 보호) — 실제 사용자 프롬프트로 시험하다 `## 권🅃` 처럼 이름이 깨지는 것을 보고 넣음.
  - `bulk`("전체 통일에 포함"): 자동 감지한 규칙 중 `{{...}}` 만 기본으로 켬. 🄳=대헌 같은 주석 전용 ID 가 "전체 통일" 한 번에 본문 전체로 퍼지는 것을 막기 위함.
  - 규칙 목록은 AI 대화 맥락과 압축 요청에도 함께 보냄(압축 시 기호를 다른 것으로 바꾸지 않도록).
- 고친 버그: 규칙 입력 칸을 옮길 때 화면을 다시 그리면서 포커스를 잃고 입력이 사라지던 문제 → `softRender` 로 포커스 복원.
- 참고: 🅄 같은 기호는 UTF-16 으로 2글자라 "대헌"→"🄳" 은 글자수가 줄지 않는다. 절약 예상치는 실제 길이 차이로 계산해 표시한다.

### 2026-11-16 (5) — 규칙 모음 탭 (AI 분석)

- 사용자 요청: 기호 치환과 별도로, AI가 프롬프트를 지속적으로 인식해 치환 규칙·컨트롤 규칙을 따로 모아 탭별로 보여 주고, 버튼을 누르면 해당 섹션으로 이동.
- 구현(`app.js` 의 "규칙 모음" 구역):
  - 분석 결과를 버전에 **섹션별로** 저장: `v.rules = { auto, by: { 섹션id: { h: 본문 해시, items:[{cat, rule, quote}] } }, last }`.
  - "지속적으로"의 해석: 섹션 본문 해시가 달라진 섹션만 다시 보내는 **증분 분석**. 탭을 열 때 바뀐 섹션이 있으면 자동으로 분석(`rulesAuto`, 끌 수 있음). 글자를 칠 때마다 호출하는 방식은 비용 때문에 택하지 않음. 탭 배지가 붉으면 반영 안 된 변경이 있다는 뜻.
  - Gemini 에 `responseMimeType: application/json` 으로 배열을 받음(`gemini()` 에 `json` 옵션 추가). 파싱 실패 시 본문에서 `[...]` 를 찾아 재시도.
  - `quote`(원문 그대로의 조각)를 누르는 순간 섹션 본문에서 찾아 그 줄로 이동(`ruleGo` → `goPos`). 본문이 바뀌어 못 찾으면 섹션 맨 위로 이동하고 안내.
  - 새 버전을 복제할 때 섹션 id 가 바뀌므로 `cloneVer` 에서 분석 결과의 키도 함께 옮김(재분석 비용 방지).
- 범위는 메인 프롬프트의 켜진 섹션만. 로어북·시작상황은 포함하지 않음(필요하면 `rulesState` 의 대상만 넓히면 됨).
- 고친 버그: 좁은 화면에서 상단 바의 "버전 관리" 버튼이 검색 버튼에 가려 눌리지 않던 문제 → 좁은 화면에서는 숨기고 "작품 정보" 탭의 버튼을 쓰게 함.
- **확인 못 한 것**: 실제 Gemini 가 분류를 얼마나 정확히 하는지, `quote` 를 원문 그대로 주는지는 가짜 응답으로만 시험했다. 실제 사용에서 분류가 어긋나면 `SYS_RULES` 문구를 조정할 것.

### 2026-11-16 (7) — 항목 메모, 접기, 찾아 바꾸기, 버전 비교 → main 에 합쳐 빌드
